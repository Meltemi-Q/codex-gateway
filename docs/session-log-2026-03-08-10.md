## 第一阶段：VPS 反代修复

### 问题
VPS 上的 Claude Opus 4.6 反代（shared20x，端口 8320）返回 401 unauthorized。

### 根因
- `~/.factory/config.json` 和 `settings.json` 中配置的 API Key 是旧的 `sk-aop-meltemi-max-2026`
- 而 proxy 的 `PROXY_KEY` 实际是 `sk-aop-460039f571bc81d5718f50783d79b24b837e20baf2b2f97f`

### 修复
- 更新 VPS 上 `config.json`、`settings.json`、`~/.claude/settings.json` 中的 API Key
- 将 `~/.claude.json` 中被 rejected 的新 key 移到 approved 列表
- 添加 Shared20x 模型条目

### 验证
- Claude Code、Droid、OpenClaw 三个客户端全部验证通过

## 第二阶段：codex-gateway 多账号轮换

### 需求
OpenAI Team 计划有 5 小时使用额度限制，需要多账号轮换来最大化可用性。

### 设计决策
- 存储：`~/.codex/` 目录下 `auth-{label}.json` 文件
- 切换条件：429 / quota / usage limit 时自动切换
- 策略：Round-robin 均匀分配
- 单账号模式：无额外开销直通

### 实现（index.mjs v2.0.0）

```
核心功能：
├── 账号自动发现（auth-*.json 文件扫描）
├── 隔离 CODEX_HOME（每账号独立目录 + 共享资源 symlink）
├── Round-robin 轮换（跳过 cooldown/disabled 账号）
├── Rate-limit 检测（429、quota、usage limit、hit your limit）
├── Auth 错误检测（refresh_token_reused、401、token expired）
├── 自动 cooldown（5 分钟，可配置）
├── 自动 disable（auth 错误永久禁用，新 token 自动恢复）
├── JWT 过期验证（启动和定期扫描）
├── Codex JSONL 错误解析（stdout 中 type:"error" / type:"turn.failed"）
├── 定期扫描（60 秒间隔 + fsWatch 实时检测）
├── 每账号用量追踪 + 全局成本统计
└── /v1/accounts 端点
```

### 关键 Bug 修复
1. **Codex 错误在 stdout 不在 stderr**：codex CLI 的 `type:"error"` 和 `type:"turn.failed"` 消息在 JSON stdout 中，需要解析 JSONL
2. **Usage limit 未被检测**：添加 `hit your.*limit` 和 `try again at` 到 rate-limit 模式
3. **Mac TLS 握手错误**：launchd plist 缺少 proxy 环境变量

## 第三阶段：API Key 认证 + 公网暴露

### 需求
VPS gateway 对外暴露，让 Win、公司服务器等设备也能用。

### 实现
- `BIND_ADDR`：可配置绑定地址（默认 127.0.0.1，设 0.0.0.0 对外）
- `GATEWAY_API_KEY`：Bearer token 认证（支持 Authorization 头和 x-api-key 头）
- 生成 API Key：`sk-cgw-c6e3614ddfecae03cf0825c027ffd64d9e77338bb1b08850`

### 部署
```
VPS systemd service:
  Environment=BIND_ADDR=0.0.0.0
  Environment=GATEWAY_API_KEY=sk-cgw-...
```

### 验证
Win、WSL、Ali、Geerji、VPS 本机全部通过，Mac 公网 IP 被 fail2ban 封了后通过 iptables 白名单恢复。

## 第四阶段：Auth-Sync（Mac → VPS 自动同步）

### 问题
OAuth refresh_token 是一次性的，同一账号在两台机器上 refresh 会冲突。

### 策略
- Mac 是唯一的登录源（需要浏览器）
- VPS 不做 refresh，只用 Mac 推过来的 token
- auth 文件变更时自动 scp 到 VPS

### 实现
- `AUTH_SYNC_TARGET`：远端 scp 目标（如 `root@vps:~/.codex/`）
- `AUTH_SYNC_SSH_OPTS`：额外 ssh 选项
- fsWatch 检测 auth 文件变更 → 2 秒 debounce → scp 推送
- `POST /v1/auth-sync` 手动触发端点
- 启动时自动执行一次初始同步

- fallbacks 从 `openai-codex/*` 改为 `codex-gateway/*`（走多账号轮换）

## 经验教训

1. **Codex CLI 错误输出在 stdout**：不在 stderr，需要解析 JSONL 的 `type:"error"` 事件
2. **refresh_token 是一次性的**：同一账号不能在两台机器上同时 refresh，要么账号隔离要么单源同步
3. **VPS SSH 频率限制**：频繁重试会被 sshd 拦截，需要间隔 60 秒以上或走跳板机
4. **Mac 代理工具接管 DNS**：新域名可能无法解析，需要手动加 `/etc/hosts` 或刷新缓存
5. **Anthropic proxy 只认 x-api-key**：第三方客户端可能用 `Authorization: Bearer`，需要两种都支持
6. **AutoClaw 选 Anthropic 协议但发 OpenAI 路径**：需要在 proxy 层做路径重写
